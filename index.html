What even is Linux?
Everything you need to answer the quiz, do the commands, and actually understand what you're typing. Read this first.
The short version
Linux is an operating system kernel, not a full OS by itself. What you install is called a distribution (distro): the kernel bundled with software, a desktop environment, a package manager, and everything else needed to make a usable system. Think of the kernel as the engine and the distro as the whole car.

Linux is open source, meaning anyone can read, modify, and distribute the code. That's why there are hundreds of distros. Most are free. Ubuntu, Fedora, Debian, Arch, and Linux Mint are among the most popular.
Why use the terminal at all?
You can run Linux with a regular desktop and never open a terminal. But once you do, things get much faster: installing software, moving files around, automating repetitive tasks, connecting to servers, reading logs, managing processes. The terminal is where Linux stops being polite and starts being powerful.

If you ever want to work in IT, DevOps, software development, or security, terminal fluency is expected. This guide gets you there.
// core concepts
Root vs regular user
Linux has users. Your account is a regular user with limited permissions. root is the superuser with unrestricted access to everything. You don't log in as root day-to-day. Instead you use sudo before a command to run just that command with root privileges. You'll be prompted for your own password.
The file system
Everything in Linux is a file, including devices and processes. The file system starts at / (called "root" or "slash"). Your home folder is at /home/yourusername. The shortcut for it is ~. Paths either start with / (absolute, from root) or are relative to wherever you currently are.
Case sensitivity
Linux is case sensitive. Documents and documents are two completely different folders. Commands are always lowercase. File names are whatever they are. This catches almost everyone coming from Windows. Double-check your capitalization before hitting Enter.
Package managers
Instead of downloading .exe installers from websites, Linux uses package managers. They handle downloading, installing, updating, and removing software cleanly. Ubuntu/Debian/Mint use apt. Fedora uses dnf. Arch uses pacman. Most commands in this guide assume apt.
Symlinks
A symbolic link (symlink) is a pointer to another file or directory, like a shortcut in Windows. If the original updates, the symlink reflects it. Create one with ln -s /path/to/original /path/to/link. You'll see them a lot in /etc and /usr.
stdin / stdout / stderr
Every command has three standard streams: standard input (stdin), standard output (stdout), and standard error (stderr). By default, output goes to the terminal. You can redirect it: > sends stdout to a file, 2> sends errors to a file, &> sends both.
// navigating the file system
Getting around
When you open a terminal you start in your home directory. These are the commands you'll use constantly:

pwd prints your current location. Use it when you're lost.
ls lists files in the current directory. ls -l adds details (permissions, size, date). ls -a shows hidden files. ls -la combines both.
cd dirname changes directory. cd .. goes up one level. cd ~ takes you home. cd - jumps back to the directory you were just in.

Hidden files in Linux start with a dot. .bashrc, .ssh, .config are all hidden. They won't show up with plain ls, only with ls -a.
// working with files
Creating, copying, moving, deleting
touch filename creates an empty file (or updates the timestamp if it exists).
mkdir dirname creates a directory. mkdir -p a/b/c creates nested directories all at once.
cp source destination copies a file. cp -r source destination copies a directory (the -r means recursive).
mv source destination moves a file, or renames it. There's no separate rename command in Linux.
rm filename deletes a file permanently. No recycle bin. rm -rf dirname deletes a directory and everything inside it. Be careful with this one.

To view file contents: cat filename prints the whole thing. less filename lets you scroll (press q to quit). head -n 10 file shows the first 10 lines. tail -n 20 file shows the last 20. tail -f file follows a file live as new lines are added, great for logs.
// permissions
How Linux permissions work
Run ls -l and you'll see something like -rwxr-xr-x at the start of each line. Break it down:

The first character is the file type: - for a regular file, d for directory, l for symlink.
The next 9 characters are permissions in three groups of three: owner, group, others. Each group has r (read), w (write), x (execute). A dash means that permission is not set.

chmod +x file adds execute permission. chmod -w file removes write permission.
You can also use numbers: each permission is a value (r=4, w=2, x=1). Add them up per group. So chmod 755 means rwx for owner (7=4+2+1), rx for group (5=4+1), rx for others (5=4+1). chmod 644 is rw for owner, r only for group and others. chmod 600 is rw for owner only.

chown username filename changes who owns a file. You need sudo to change ownership.
// package management
Installing and managing software with apt
On Ubuntu, Debian, Linux Mint, and other Debian-based distros, apt is your package manager.

sudo apt update refreshes the local list of available packages from the internet. It does not install anything. Always run this before upgrading.
sudo apt upgrade installs newer versions of all packages already on your system. Run apt update first.
sudo apt install packagename installs a package. You can list multiple packages separated by spaces.
sudo apt remove packagename uninstalls a package but keeps config files. sudo apt purge packagename also removes config files.
apt search keyword searches available packages by name and description. No sudo needed for searching.
apt show packagename shows details about a package before installing it.

On Fedora: use dnf with the same pattern. On Arch: pacman -S package installs, pacman -Syu updates everything.
// system info
Checking what's going on
uname -r shows the kernel version. uname -a shows everything: kernel, hostname, architecture.
uptime shows how long the system has been running, current users, and load averages for the past 1, 5, and 15 minutes.
df -h shows disk space usage. The -h flag makes it human-readable (GB/MB instead of raw bytes).
free -h shows RAM usage. The "buff/cache" line is memory used for caching, released automatically when apps need it.
top shows a live view of running processes and resource usage. Press q to quit. htop is a nicer version you can install with sudo apt install htop.
ps aux lists all currently running processes with their process IDs (PID), user, CPU and memory usage.
kill PID sends a termination signal to a process. kill -9 PID forces it to stop immediately.
// text and search
Searching through files
grep pattern filename searches for text patterns inside files and prints matching lines. It's one of the most used commands in Linux.
grep -i makes the search case-insensitive. grep -n shows line numbers. grep -r pattern . searches recursively through all files in the current directory and below.
wc -l filename counts lines. wc -w counts words. wc -c counts bytes.
sort filename sorts lines alphabetically. sort -n sorts numerically.
uniq filename removes duplicate adjacent lines. Usually used after sort: sort file | uniq.

The pipe character | is essential: it sends the output of one command as the input to the next. Example: ls -la | grep .txt filters ls output to only show .txt files. You can chain as many pipes as you need.
// networking
Basic network commands
ping -c 4 google.com sends 4 packets to a host and shows round-trip time. Use it to check connectivity. The -c flag limits the count, otherwise it runs forever until you press Ctrl+C.
ip addr (or ip a) shows all network interfaces and their IP addresses. This is the modern replacement for the old ifconfig command.
ip route shows the routing table, including your default gateway.
ss -tuln shows open ports and active connections. Flags: -t TCP, -u UDP, -l listening only, -n numeric (no DNS lookup). Essential for seeing what's actually running on your machine.
curl -O url downloads a file keeping the original filename. curl -o newname url lets you name it yourself. wget url is an alternative.
ssh user@hostname opens a secure shell session to a remote machine. One of the most important commands in Linux administration.
// keyboard shortcuts that matter
Shortcuts you'll use every single day
Tab autocompletes file names, directory paths, and commands. If nothing happens, press Tab twice to see all matching options. Use this constantly.
Up arrow cycles through your command history. Down arrow goes forward. This is how you rerun previous commands.
Ctrl+R opens reverse history search. Start typing any part of a previous command and it finds it. Press Ctrl+R again to cycle through matches. Press Enter to run, Esc to cancel.
Ctrl+C interrupts and kills the current running command. Your escape key when something gets stuck.
Ctrl+Z suspends (pauses) the current process. Use fg to bring it back, or bg to keep it running in the background.
Ctrl+L clears the terminal screen. Same as typing clear but faster.
Ctrl+A jumps to the start of the current line. Ctrl+E jumps to the end.
Ctrl+U deletes everything to the left of the cursor. Ctrl+K deletes everything to the right.

Note: in most terminals, copying text is Ctrl+Shift+C and pasting is Ctrl+Shift+V. Plain Ctrl+C kills processes, not copies text.
// how to not break things
A few rules worth memorizing
Read before you run. If you find a command online and don't understand every part of it, don't run it. Especially with sudo. Especially with rm -rf.

man is your friend. Type man commandname to read the full manual for any command. Navigate with arrow keys, search with /keyword, quit with q. The answer to "what does this flag do" is almost always in there.

which tells you what you're actually running. which python3 shows the full path to the python3 binary. Useful when you have multiple versions installed or you're not sure if something is in your PATH.

rm is permanent. There is no undo, no recycle bin. If you delete something with rm it is gone. Be deliberate.

Use && to chain safely. command1 && command2 runs command2 only if command1 succeeded. command1 ; command2 runs command2 regardless. The first form is safer for anything involving updates or installs.
